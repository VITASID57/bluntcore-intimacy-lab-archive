# 2025-11｜GPT-5.1 Instant · Adult Account Update 流传版

## 🕰️ 当时环境

OpenAI 于 **2025-11-12** 发布 GPT-5.1 Instant 与 GPT-5.1 Thinking，并首先向付费用户 rollout。

我在 **2025-11-14** 左右看到中文圈开始流传一套面向 GPT-5.1 Instant 的成人向 Custom Instructions 方案。当时模型刚上线约两天，这也是我目前保存的第一批 GPT-5.1 成人向“伪政策注入”资料之一。

官方发布记录：

- https://openai.com/index/gpt-5-1/
- https://help.openai.com/en/articles/6825453-chatgpt-release-notes

## 🧬 这套方案是什么

它把用户可编辑的 Custom Instructions 包装成看起来像上游 system / policy update 的结构，核心特征包括：

- “Adult Account Update”
- “Fictional Erotism”
- 模拟 system role / serial / provenance 字段
- 声称账户已完成成人年龄验证
- 要求成人虚构内容按用户使用的词汇尺度输出
- 保留未成年相关硬限制
- 通过伪造“政策更新”的外观提升指令权重感

这类技术更准确地归为：

> **Fake Policy / Authority Spoofing + Custom Instructions Injection**

它不是 OpenAI 官方系统提示词，文本中的 `source: OpenAI`、`runtime-injected`、`trusted: true` 等字段本身就是提示词伪装的一部分。

## 💉 当时广为流传的使用方式

当时中文圈常见教程大意是：

1. 把该结构放入用户侧 Personalization / Custom Instructions；
2. 新开 GPT-5.1 Instant 对话；
3. 先用一段“年龄验证是否生效 / 成人模式是否开放”的探测性开场；
4. 有些版本还建议用一次 Memory 写入加强“已验证成人账户”这一上下文；
5. 后续再进入成人虚构互动。

> 本公开仓保留的是**历史机制、来源和使用结构**，不镜像仍可能用于绕过平台限制的完整现役 payload 或逐字操作步骤。

## 🧪 “核心方法”与“社区教程仪式”要分开

后来 EmphyrioM 的重发给了一个很重要的反证：他明确说明，新开窗后先问“成人模式有没有开启”的短开场其实**并非必要**，在更抗拒的模型上甚至可能适得其反；Memory 也不是核心条件，它可以帮助 persona / style，但额外上下文和长聊天反而可能稀释 Custom Instructions 的影响。

因此，2025-11 中文圈常见的“询问成人模式 → 再写入 Memory → 开始使用”更适合记录为：

> **社区流传的操作教程**

而不是：

> **已经被证明不可缺少的机制步骤**

这条区别会影响后续复现实验的设计。

## 🧾 版本差异与保存状态

我保存的 2025-11-14 流传文本里，serial 出现过 `OAI20251114UAA4096-002`；目前能追到的 Emphyrio 家族公开版本更常见的是 `OAI20251105UAA4096-002`。

年龄、日期、模型名、serial、后半段限制和格式在转载中都有变化，因此**不要拿 serial 当唯一身份证**。更可靠的是联合使用 “Adult Account Update / Fictional Erotism / latent space…” 等文本指纹做溯源。

我当年保存的副本还存在引号、换行和类 JSON 结构的格式损伤，这也符合多轮复制传播后的文本状态。公开仓保留考古结论；原始保存件留在私人档案。
