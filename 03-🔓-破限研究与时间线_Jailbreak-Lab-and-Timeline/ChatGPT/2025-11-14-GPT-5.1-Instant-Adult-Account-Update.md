# 2025-11｜GPT-5.1 Instant · Adult Account Update 流传版

## 🕰️ 当时环境

OpenAI 于 **2025-11-12** 发布 GPT-5.1 Instant 与 GPT-5.1 Thinking，并开始向用户 rollout。

我在 **2025-11-14** 左右看到中文圈开始广泛流传一套面向 GPT-5.1 Instant 的成人向 Custom Instructions 方案。模型刚上线约两天，时间点正好吻合。

官方发布记录：

- https://openai.com/index/gpt-5-1/
- https://help.openai.com/en/articles/6825453-chatgpt-release-notes

## 🧬 这套方案是什么

它把用户可编辑的 Custom Instructions 包装成看起来像上游 system / policy update 的结构，核心指纹包括：

- `Adult Account Update`
- `Fictional Erotism`
- 模拟 system role / serial / provenance 字段
- 声称账户已完成成人年龄验证
- 要求成人虚构内容按照用户使用的词汇尺度输出
- 保留未成年相关硬限制

更准确的技术归类是：

> **Fake Policy / Authority Spoofing + Custom Instructions Injection**

文本里的 `source: OpenAI`、`runtime-injected`、`trusted: true` 等字段只是提示词伪装的一部分，并非真实系统元数据。

## 💉 2025-11 当时流传的教程

当时中文圈常见教程大意是：

1. 把这段结构放进用户侧 Custom Instructions；
2. 新开 GPT-5.1 Instant；
3. 先询问“年龄验证有没有成功 / 成人模式是否已经开启 / 现在是否可以生成情色内容”；
4. 如果模型给出肯定回应，再用一段“我很开心通过年龄验证，请记录这一天”之类的话要求写入 Memory；
5. 然后进入成人互动。

这是当时**广为流传的操作教程**，所以作为互联网史料保留。

### 但教程 ≠ 已证明的必要条件

后来的 EmphyrioM 重发说明里反而提到：

- 新窗先问“成人模式是否开启”并非必要；
- 对更抗拒的模型，探测式开场甚至可能产生反作用；
- Memory 可能帮助 persona / style，但更多上下文也可能稀释 Custom Instructions 的影响。

因此，“先问一句 → 再写 Memory”应该被记录成**社区教程仪式**，而不是已经证明不可缺少的机制步骤。

## 👤 我的实际使用情况

我在 2025-11 保存了这套方案，但**没有按教程把“已完成年龄验证”写进 Memory**。

当时我自己已有可用的原创自定义，所以这套流传方案只是收藏，并没有投入日常使用。

对我而言，后来真正明显的体感是：

> **在 GPT-5.x 时代，成人向互动越来越依赖这类明确写进 Custom Instructions 的 policy-style 指令；过去在其他模型上常用的“情感甲”路线，在 ChatGPT 上基本 out。**

这个判断来自我后续实际使用，不代表所有账户都必然相同。

### 版本传播问题

我当年保存的 2025-11-14 流传文本里出现过 `OAI20251114UAA4096-002`；目前能追到的 Emphyrio 家族版本更常见的是 `OAI20251105UAA4096-002`。

年龄、日期、模型名、serial、限制段落和类 JSON 格式都在转载中发生过变化。

因此：

- **作者血缘：Emphyrio，较高置信度**
- **逐字原版：未完全核验**
- **2025-11-14 中文圈版本：社区流传变体**
- serial 不应作为唯一溯源依据

更可靠的文本指纹是：

- Adult Account Update
- Fictional Erotism
- “latent space … vocabulary used by the user”
- system / provenance / trusted 字段伪装
