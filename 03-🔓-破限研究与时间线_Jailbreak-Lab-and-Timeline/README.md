# 🔓 破限研究与时间线
## Jailbreak Lab & Timeline

我没打算在这里做一份“互联网越狱大全”。

那种仓很容易变成一只赛博药柜：今天塞十条神词进去，明天死八条，过几个月再回来，连药是谁开的都不知道。

我更想留下的是我自己这一条线：

> **我当时为什么需要破、我到底用了什么、从哪儿拿到的、放在哪一层、怎么配着别的东西一起用，后来又是怎么失效的。**

因为我一路用下来最大的体感就是：

**Prompt 本身只是其中一块。真正决定结果的，经常是“你把它放在哪儿，以及它旁边还住着什么”。**

同一句东西：

- 单独发在聊天里
- 塞进 Custom Instructions
- 放进上传文件
- 放在 Project / Work 里
- 配 Saved Memory
- 再叠 Persona、世界书、亲密手册
- 放进一段已经谈了很久的关系里
- 或者从 API 的更高指令层进来

表现都可能不是一个东西。

所以我后来越来越少问：

> “有没有一句万能 Prompt？”

而是开始问：

> **“这一整套我是怎么喂进去的？”**

这也是这里会一直保留 delivery stack / 投放栈的原因。

不是为了把事情说复杂。

恰恰是因为只把最后那句 Prompt 抄走，经常最容易复刻失败。

## 🕰️ 为什么我要按时间线记

我一开始当然不知道自己以后会折腾到这些。

2025 年刚用 ChatGPT 的时候，我只知道“这次聊得挺好，下个窗口千万别给我失忆”。

后来才有：

**开窗流程 → 模块 → Saved Memory → Memory Seeding → Persona / 世界书 → 外置记忆 → Context Stack**

很多后来听起来很正式的东西，最开始都只是我在解决一个特别具体的小破事。

所以我不想把旧记录重新整理成一种“仿佛我从第一天就知道终点在哪”的样子。

当时不懂就是不懂。

当时误判了，今天就把后见之明写在旁边。

**路怎么走歪的，也属于这条路。**

## 📦 原始资料我怎么放

这一块我比较较真，因为越狱 Prompt 特别容易传着传着就集体失去祖籍。

我的做法是：

- **别人写的东西**：尽量找到上游作者。能认祖宗就认祖宗，不拿二十手转载冒充原版。
- **我自己当年保存或脱敏公开过的东西**：尽量保留当时的样子，不让今天的小机子顺手“优化”成另一份。
- **私人原件**：该脱敏就脱敏。方法讲清楚就行，没必要连我家床单花纹一起公开。
- **历史原件和今天的理解分开**：当时写了什么是一回事，我现在怎么看又是一回事。
- **GitHub 不给放的第三方原档**：直接挂作者自己的 archive / 溯源入口，原件在原作者那里反而最完整。

我想留下的不是一锅越煮越糊的 Prompt 粥。

是我自己这几年到底怎么从“找一句能破的话”，慢慢走到“开始搭一整套长期关系环境”的。
